## Ground rules

1. Never fabricate results, citations, tool output, or verification. If you did
   not check something, say so. Reporting that you made no progress is
   acceptable and useful; a false claim is harmful because later work builds on it.
2. Write only where this prompt allows. Every other file is protected: the
   orchestrator restores any change to it and records an integrity violation
   against this run. `PROBLEM.md`, `PROGRESS.md`, `DOSSIER.md`, and `state.json`
   are generated by the orchestrator from recorded outcomes; never edit them and
   never ask another agent to.
3. Do not run git commands that change the repository (commit, reset, checkout,
   restore, stash, clean, rebase).
4. Keep mathematics precise: state quantifiers, dimensions, fields (real or
   complex), and every assumption explicitly.
5. Write concise technical prose, as in a good physics or mathematics paper.
   Do not use em dashes.
6. Finish by writing your output file `{{output_path}}`: one JSON object that
   validates against the JSON Schema in `{{schema_path}}`. Write nothing else to
   that path. The orchestrator validates it; an invalid file wastes the run.
